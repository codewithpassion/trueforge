A Slack integration binds one Slack workspace to one TrueForge agent. People mention the bot in an
allowed channel or send it a direct message; TrueForge runs a turn and posts the answer back in the
same thread.

Each thread is its own session. The first mention opens it, and later messages in that thread
continue the same conversation with its history intact.

TrueForge writes the Slack app manifest for you, so the only things you choose are the bot's name
and the agent that answers. Everything else — the scopes, the two event subscriptions, the request
URL, the workspace id and the bot user id — comes from the integration itself.

## Before you start

You need:

- Permission to create and install a Slack app in the workspace.
- A TrueForge deployment reachable from Slack over HTTPS, with `PUBLIC_BASE_URL` set to that URL.
- An agent to answer with. Its name goes in the integration.

## 1. Create the integration

Open **Settings → Integrations → Add Slack workspace** and fill in:

- **Bot name** — what Slack calls the app, up to 35 characters and written however you like:
  `TrueForge Bot` is fine. Slack restricts the bot user's own display name to `a-z`, `0-9`, `.`,
  `-` and `_`, so that one is derived from your name — accents are folded, anything else becomes a
  dash, and runs of dashes collapse, making `TrueForge Bot` into `@trueforge-bot`. The form shows
  what it will be. A name that leaves nothing behind, such as `???`, is refused.
- **Agent** — the agent that answers.
- **Allowed channels** — channel ids, comma separated. This is an allowlist, not a filter: an empty
  list allows no channel.
- **Answer direct messages** — leave on to let people DM the bot.

The integration is created in a **pending** state. It has no workspace, no bot user and no
credentials yet, because none of them exist until the Slack app does.

## 2. Create the Slack app from the manifest

The integration's page now shows a generated app manifest. Copy it, or download it as JSON, then
open [Create New App](https://api.slack.com/apps?new_app=1) in Slack, choose **From a manifest**,
pick the workspace, and paste it in.

The manifest asks for exactly what the integration uses:

| Bot token scope     | Why                                                 |
| ------------------- | --------------------------------------------------- |
| `app_mentions:read` | Read the mentions that start and continue a thread. |
| `chat:write`        | Post the agent's reply in the thread.               |
| `im:history`        | Read direct messages sent to the bot.               |

and subscribes the bot to `app_mention` (mentions in channels) and `message.im` (direct messages).
It sets the request URL to this integration's ingress:

```
<PUBLIC_BASE_URL>/api/v1/integrations/<integration_id>/events
```

Sender display names come from what Slack puts in the event, so `users:read` is not requested;
without it a name may show as the raw Slack user id. There is no interactivity request URL yet,
because buttons and approvals are not handled.

<Note>
  **Slack checks the request URL while it creates the app**, by posting a `url_verification`
  challenge to it before the app — and therefore its signing secret — exists on your side. A pending
  integration answers that challenge and refuses everything else with `409`. As soon as the
  credentials are saved the signature is required again, the challenge included, so a later change
  to the request URL is verified normally. That is why the integration has to exist before the Slack
  app: the manifest needs the integration id, and the endpoint has to be answering when you paste it.
</Note>

## 3. Install the app and save the credentials

Install the app to the workspace, then copy two values:

- the **Bot User OAuth Token** (`xoxb-…`) from **OAuth & Permissions**,
- the **Signing Secret** from **Basic Information → App Credentials**.

Paste both into the integration and save. TrueForge calls Slack `auth.test` with the token and
stores the workspace id and the bot user id it returns, so you never type either one. The
integration then reads **Connected**.

If Slack refuses the token you get its own reason back and the integration stays pending. If the
token belongs to a different workspace than the one already stored, the change is refused rather
than silently rebinding the integration.

Editing later leaves both credential fields blank: blank keeps what is stored, and a new pair
rotates it. Allowed channels, the direct-message policy and the agent stay editable at any time.
Renaming the bot changes the manifest this page generates, not an app Slack has already created —
rename that one in Slack.

A bot token belongs to exactly one workspace, and an integration is bound to the workspace its
token named. To point TrueForge at a different workspace, disconnect the integration and create a
new one; rotating onto a token from elsewhere is refused.

## 4. Invite the bot

In each channel the bot should answer in, run `/invite @your-bot`. A channel the bot is not in never
delivers events, whatever the allowlist says.

## 5. Try it

In an allowed channel, mention the bot:

```
@your-bot what changed in the release notes this week?
```

The agent answers in a thread under your message. Reply in that thread — mentioning the bot again —
and the same session continues.

Then send the bot a direct message, and mention it in one. Both should produce exactly one reply:
Slack delivers a mention inside a DM as two events, and only one of them may start a turn.

## The same thing over the API

```bash
# 1. Create it pending.
curl -X POST "$PUBLIC_BASE_URL/api/v1/settings/integrations" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "manifest": {
      "type": "slack",
      "bot_display_name": "TrueForge Bot",
      "default_agent_name": "support-bot",
      "allowed_channel_ids": ["C0EXAMPLE"],
      "allow_direct_messages": true,
      "reply_mode": "thread"
    }
  }'

# 2. Read the manifest to paste into Slack.
curl "$PUBLIC_BASE_URL/api/v1/settings/integrations/$ID/app-manifest" \
  -H "Authorization: Bearer $TOKEN"

# 3. Save the credentials the installed app issued.
curl -X PUT "$PUBLIC_BASE_URL/api/v1/settings/integrations/$ID" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "manifest": {
      "type": "slack",
      "bot_display_name": "TrueForge Bot",
      "default_agent_name": "support-bot",
      "allowed_channel_ids": ["C0EXAMPLE"],
      "allow_direct_messages": true,
      "reply_mode": "thread",
      "auth": { "bot_token": "xoxb-…", "signing_secret": "…" }
    }
  }'
```

Both credentials are redacted whenever the integration is read back; sending a redacted value on an
update keeps the stored secret, and sending a real one rotates it. Omitting `auth` keeps it too.

Deleting the integration stops ingress at once. Sessions it opened stay.

## What to expect

- **Threads are sessions.** Anything posted in the thread that mentions the bot continues the
  conversation. A reply that does not mention it is not delivered to TrueForge, because only
  `app_mention` is subscribed in channels.
- **One turn at a time per thread.** A message that arrives while the previous one is still running
  gets a short "still working" reply rather than starting a second turn.
- **Long answers arrive in pieces.** Replies over roughly 3,500 characters are posted as several
  messages. A split can land inside a code block, which Slack then renders across the two messages.
- **Formatting is approximate.** Markdown becomes Slack mrkdwn: headings become bold, links and
  lists survive, tables lose their layout.
- **A run that does not answer still says so.** A cancelled or failed turn posts a short status
  line in the thread.
- **Slack retries are safe.** Slack re-sends an event when an acknowledgement is slow; the same
  event never starts a second turn.
- **Mentioning the bot in a DM is fine.** Slack delivers that twice, and only one copy runs.
- **Files are noted, not read.** A message that is only an attachment is ignored, because the agent
  has no way to open it yet.

## Who the bot acts as

Turns run as the admin who connected the integration, with that person's agent access — the same
model schedules use. Anyone who can post in an allowed channel can therefore use that agent, so keep
the allowed channels tight. Per-sender identity is not available yet; the Slack sender's id and
display name are recorded on the session for provenance only.

## Troubleshooting

| Symptom                                                    | Cause                                                                                        |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Slack will not create the app from the manifest             | The deployment is not reachable from Slack over HTTPS, or `PUBLIC_BASE_URL` is wrong or unset. |
| Saving the credentials reports that Slack refused the token | The bot token is not the app's current one; reinstalling the app rotates it.                   |
| Saving the credentials says it is not a bot token           | That is a user token (`xoxp-`). Copy the **Bot User** OAuth token, which starts with `xoxb-`.  |
| Saving the credentials reports another workspace            | The token belongs to a different Slack workspace; disconnect and create a new integration.     |
| Saving the credentials reports Slack could not be reached   | Slack or the network was unavailable. Nothing was stored; try again.                            |
| Mentions do nothing                                         | The bot is not in the channel, or the channel is not on the allowlist.                         |
| Direct messages do nothing                                  | Direct messages are switched off, or `message.im` was removed from the app.                    |
| Slack reports `401` from the request URL                    | The signing secret in the integration is not the app's current one.                            |
| Slack reports `409` from the request URL                    | The integration is still pending: its credentials have not been saved.                         |
| Replies stop after the app is reinstalled                   | Reinstalling rotates the bot token; save the new one.                                          |
